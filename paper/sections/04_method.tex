\section{Policy-Consistent EGC-TTRL}

\subsection{Policy-consistent runtime (serving transaction)}
Every generation request is drawn from a \emph{request-scoped} RNG:
$\mathrm{seed}=\mathrm{H}(\mathrm{protocol}, \mathrm{stream\_seed},
\mathrm{task\_id}, \mathrm{turn\_id}, \mathrm{policy\_version},
\mathrm{purpose}, \mathrm{branch\_group},\dots)$ where \texttt{purpose}
separates production first attempts from credit rollouts, branches, and
canaries. A \textbf{colocated backend} runs training and serving on the
same PEFT model (slow but provably consistent): the model that samples
the next first attempt is the model that received the update. Adapter
commits are atomic: the candidate state is hashed, the canary checks (a)
adapter hash equality, (b) parent-vs-candidate logit KL on a fixed
prompt, (c) an observably changed deterministic rollout; only then does
the policy version advance. Rollback restores the previously served
state from a stack. The A0 gate verifies bitwise identity under
repeated seeds and that update-arm RNG draws never shift production
seeds.

\subsection{Cross-task evidence replay}
Single-task updates are too weak and noisy (v1). We aggregate
\emph{evidence rows} across tasks in a session-scoped buffer:
each row is the canonical action sequence extracted from a rollout
(lookup/exploration calls removed; the verification lookup step retained
when the credited action acts on evidence-discovered entities), with its
group-relative signed advantage, producer prompt/completion ids, and a
hash. Updates run every $K{=}2$--4 tasks on a batch sampled
\textbf{intent-balanced} (equal budget per tool workflow) plus
20--40\% \emph{anchor} rehearsal rows (canonical demo trajectories) to
guard against catastrophic forgetting. All arms share the same buffer
capacity and update-token caps.

\subsection{Evidence-gated counterfactual credit (EGC)}
At a decision point (after the first turn reveals state), we construct a
grammar-valid counterfactual set: for entity-selection decisions the set
is \emph{goal-entity vs.\ evidence-discovered entity} (e.g., the refund
target named in the goal vs.\ the user returned by
\texttt{lookup\_order}), plus model proposals for coverage. Each
candidate action executes on $R{=}4$ fresh snapshots of the same task
instance; the utility matrix $U[G,R]$ yields group-relative signed
credit via paired credit with across-seed variance. Positive-credit
actions become replay rows; the reliability gate requires
$|\mathrm{credit}|>0.05$. The naive arm uses the same replay machinery
with terminal trajectory utility instead of branch credit.

\subsection{Evaluation protocol}
Prequential first-attempt AUPC (hidden oracle used only as an L0
diagnostic, never in training); sealed held-out template appears only in
the final phase and is never trained on; statistics use exact two-sided
sign-flip over paired seeds plus hierarchical bootstrap; runs carry
immutable manifests (seed list, policy versions, adapter hashes, buffer
stats, violations).
